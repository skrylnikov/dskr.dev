# Путешествия

Текст хранится в MDX, медиа — в S3/RustFS. Общий адрес `/media/` и bucket `dskr-media-originals`/`dskr-media-published` используются для медиа всего сайта, включая путешествия и обычный блог. Обычная сборка читает только локальные манифесты; S3 и ffmpeg ей не нужны. Материалы поездки публикуются только после проверки текста и загрузки медиа.

## Поездка и записи

Пример `src/content/travel/trips/kaliningrad.ru.mdx` (даты ниже условные):

```mdx
---
slug: kaliningrad
locale: ru
title: Калининградская область
description: Несколько дней у Балтийского моря.
destinations: [Калининград, Зеленоградск]
startDate: 2026-10-20
endDate: 2026-10-23
collage: [coast/forest, coast/sea, coast/city]
draft: true
---

Вступление к поездке.
```

Глава `src/content/travel/entries/kaliningrad/coast.ru.mdx`:

```mdx
---
slug: coast
trip: kaliningrad
locale: ru
kind: chapter
order: 0
title: Куршская коса и Зеленоградск
description: Танцующий лес, море и прогулка по городу.
collage: [coast/forest, coast/sea, coast/city]
draft: true
---

## Танцующий лес

Рассказ об этом месте.

<MediaGallery gallery="coast" />
```

Заметка `entries/kaliningrad/evening.ru.mdx`:

```mdx
---
slug: evening
trip: kaliningrad
locale: ru
kind: note
order: 1
date: 2026-10-20
draft: true
---

<MediaGallery gallery="evening" />

Ну а закончил вечер дегустацией.
```

Заголовок заметки необязателен. `order` уникален среди всех записей поездки на одном языке. В коллаже от трёх до восьми ссылок на фото; обычно шесть. Кадры раскладываются рядами с сохранением пропорций, без обрезки. Импорт выбирает до шести фотографий из разных частей записи; если фотографий меньше трёх, кадры повторяются. Даты без времени обозначают календарный день.

Для перевода создайте соседние `.en.mdx` с теми же slug и `locale: en`, переведите текст и метаданные. Галереи остаются общими, их alt/подписи содержат `ru` и `en`. Убирайте `draft` только после редакторской проверки и публикации медиа. Черновики не создают HTML, ссылки и sitemap-записи; опубликованная глава внутри черновика поездки тоже скрыта.

## Подготовка и публикация медиа

Для превью ссылок поездки и глав используются отдельные JPEG-коллажи из кадров `collage`, без обрезки. RU/EN переиспользуют одно изображение. После изменения кадров подготовьте и опубликуйте превью до выкладки сайта:

```sh
node --import tsx scripts/travel-previews.mts prepare
node --env-file-if-exists=.env --import tsx scripts/travel-previews.mts publish
```

Команда читает локальные JPEG-производные из `.state/travel/objects` и создаёт общий манифест `src/data/travel-previews.json`. Ключи зависят от порядка кадров, их содержимого и параметров обработки; повторный запуск переиспользует готовые файлы. JPEG загружаются в приватный опубликованный bucket и выдаются через `/media/`. Обычная сборка читает только манифест. Если коллаж ещё не подготовлен, превью временно использует первый кадр. Telegram может сохранять старое превью уже отправленных ссылок.

Видео автоматически запускается при открытии в просмотрщике и при переходе на видеокадр. Сначала пробуем воспроизведение со звуком; если браузер блокирует его, повторяем без звука. Если автозапуск полностью запрещён, остаётся стандартная кнопка Play. При смене кадра и закрытии воспроизведение останавливается. До открытия видео не загружается.

Нужны Node/pnpm из проекта и установленные `ffmpeg`/`ffprobe`, `cjxl` и `djxl` (macOS: `brew install ffmpeg jpeg-xl`; Debian/Ubuntu: `apt install ffmpeg libjxl-tools`). Создайте JSON-вход в `.state/travel/` (исходники и локальные пути не коммитятся):

```json
{
  "id": "evening",
  "items": [{
    "id": "tasting",
    "file": "/absolute/path/photo.jpg",
    "alt": { "ru": "Дегустационный сет на столе", "en": "A tasting selection on the table" },
    "caption": { "ru": "Вечер после прогулки", "en": "An evening after the walk" }
  }]
}
```

`file` может быть абсолютным либо относительно входного JSON. Для видео используются MP4/MOV/M4V/WebM/MKV; остальные файлы проверяются Sharp как изображения. Порядок `items` — порядок просмотра.

```sh
pnpm travel:media prepare .state/travel/evening.json
```

Команда создаёт версионированные файлы в `.state/travel/objects`, локальную запись подготовки и `src/content/travel/media/evening.json`. Изображения поворачиваются, EXIF удаляется, размеры не увеличиваются. Для каждого размера создаются JPEG XL, WebP и JPEG; JXL кодируется из очищенного и уменьшенного оригинала, а не из повторно сжатого JPEG. Для JXL явно включён `--progressive`, для JPEG — прогрессивное кодирование. Браузер выбирает поддерживаемый формат, JPEG остаётся запасным вариантом. Просмотрщик проверяет поддержку JXL локальной картинкой без сетевого запроса. Видео приводится к MP4 H.264/AAC с fast-start и ограничением разрешения. Первый кадр извлекается в PNG и проходит ту же обработку, что фотографии: варианты размеров записываются в `posterSources`, а `poster` содержит полный JPEG для совместимости. Старые манифесты без `posterSources` продолжают работать; повторная подготовка добавляет варианты без перекодирования готового MP4. Повторный запуск использует готовые результаты. После изменения алгоритма обработки нужно изменить `recipe` или `jxlRecipe` в скрипте. У JXL и превью отдельные ключи: изменение их обработки не пересоздаёт существующие JPEG, WebP и видео.

Добавьте переменные загрузчика из `.env.media.example` в игнорируемый `.env`. Команда `pnpm travel:media` читает его автоматически; уже заданные переменные окружения имеют приоритет:

```sh
MEDIA_S3_ENDPOINT=https://rustfs.home.dskr.dev
MEDIA_S3_REGION=us-east-1
MEDIA_S3_ORIGINALS_BUCKET=dskr-media-originals
MEDIA_S3_PUBLISHED_BUCKET=dskr-media-published
MEDIA_S3_ACCESS_KEY_ID=YOUR_UPLOADER_KEY
MEDIA_S3_SECRET_ACCESS_KEY=YOUR_UPLOADER_SECRET
```

Публикация явно выбранной галереи:

```sh
pnpm travel:media publish evening
```

Исходники отправляются в закрытый bucket, производные — в отдельный закрытый bucket, доступный через публичный медиашлюз. Команда проверяет размеры объектов. Доступ к опубликованным производным публичный; не загружайте туда приватные вложения и не считайте `draft: true` способом скрыть уже загруженный файл.

Загрузчик и шлюз используют один ключ `MEDIA_S3_ACCESS_KEY_ID`/`MEDIA_S3_SECRET_ACCESS_KEY` с правами из `uploader-policy.json` инфраструктурного overlay. Для шлюза он хранится в зашифрованном SOPS Secret `media-s3`. Шлюз настроен на `dskr-media-published` и отключает листинг; сам ключ при этом имеет права чтения и записи в обоих bucket, включая оригиналы.

Конфигурация шлюза и политики доступа находятся в инфраструктурном репозитории: `apps/prod-selectel-msk/media/`. Этот overlay требуется включить отдельно после настройки секретов и проверки медиа. dskr.photos и IndieWeb не используются для доставки путешествий.

## Перенос Telegram

Поддерживается JSON (`result.json`) или HTML (`messages.html`) с фото и видео. Для HTML автоматически читаются соседние `messages2.html`, `messages3.html` и следующие страницы. Создайте mapping JSON с фактическими датами и идентификаторами сообщений:

```json
{
  "trip": "kaliningrad",
  "title": "Калининградская область",
  "description": "Истории из поездки",
  "destinations": ["Калининград", "Зеленоградск"],
  "startDate": "2026-10-20",
  "entries": [
    { "slug": "city", "kind": "chapter", "title": "Калининград", "description": "Прогулка по городу", "messageIds": [101, 102] },
    { "slug": "evening", "kind": "note", "messageIds": [103] }
  ]
}
```

```sh
pnpm travel:import /path/to/export/result.json .state/travel/mapping.json
# Или уже выгруженный HTML:
pnpm travel:import /path/to/export/messages.html .state/travel/mapping.json
```

Порядок `entries` задаёт ленту; внутри записи сохраняется порядок сообщений в экспорте. Импорт чередует медиаподборки и текст, сохраняет форматирование и экранирует исполняемый синтаксис MDX. HTML читается как данные, скрипты не выполняются; сохраняются rich-блоки, смешанные коллажи и подписи. Для фотографий используются ссылки на полные файлы, а не `*_thumb.jpg`. Поддерживаются даты Desktop `DD.MM.YYYY` и русского нативного клиента. Неизвестные даты и rich-блоки вызывают ошибку вместо молчаливой потери содержимого.

Импорт создаёт только русские черновики, входы подготовки галерей и `.state/travel/import/{trip}/report.json`. Если один Telegram-пост нужно разделить на главу и заметку, после импорта перенесите соответствующие MDX-блоки в отдельную запись, сохранив `sourceMessageIds`.

Сначала устраните отсутствующие файлы из отчёта, проверьте границы подборок и подписи. Экспорт не всегда содержит границы Telegram-альбомов: импорт группирует последовательные вложения до очередного текста; при необходимости объедините подборки вручную. Плейсхолдеры `missing-photo` в коллажах нужно заменить реальными ссылками. Повторный запуск не перезаписывает существующие MDX и входы галерей; после неполного экспорта исправьте черновики вручную либо удалите только проверенные сгенерированные файлы для повторного импорта.

Подготовьте каждый вход из `.state/travel/import/{trip}/*.json` (кроме `report.json`), уточните alt/подписи, переведите поездку и записи на EN, затем публикуйте выбранные галереи. Не восстанавливайте отсутствующие тексты или даты по догадкам.

## Проверки и локальный preview

```sh
pnpm travel:test
pnpm travel:e2e
pnpm test
```

Browser-тесты используют Chromium, установленный через `pnpm exec playwright install chromium`, и ffmpeg. Они создают синтетическую поездку с 200 медиа в `.state/travel-fixtures`, собирают отдельный `.state/travel-dist` и запускают локальный сервер. Тестовый контент не попадает в обычный `pnpm build`.

Для ручного просмотра тестовой поездки:

```sh
pnpm travel:fixtures
TRAVEL_CONTENT_ROOT=.state/travel-fixtures pnpm dev
```

В dev изображения требуют настроенного `/media/`; браузерные тесты подставляют тестовые медиа своим сервером. Для полностью работающего локального preview используйте собранный тестовый сайт:

```sh
TRAVEL_TEST_BUILD=1 TRAVEL_CONTENT_ROOT=.state/travel-fixtures pnpm build
node tests/travel/server.mjs
```

Откройте `/travel/sample-trip/` на `http://127.0.0.1:4399`. Это демонстрационные данные, не перенесённая калининградская поездка.
